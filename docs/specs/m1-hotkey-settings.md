## 一、设置窗口（D047）

### 1.1 打开与关闭

- 托盘右键菜单顺序：**设置…**、打开主窗口、退出 LexTrail。托盘左键仍然打开主窗口。
- 窗口标签 `settings`，Rust 端 `settings_window.rs`，做法和 `main_window.rs` 相同：
  - 按需创建、关闭即销毁；和悬浮窗、主窗口共用同一个 WebView2 环境（D010）。
  - 已经打开时再点"设置…"，只把它带到前面（最小化了就先还原），不重新加载。
  - 页面加载完成后才显示，背景色和页面相同，不闪白。
- 窗口：标题"LexTrail 设置"，逻辑尺寸 720×520，最小 600×420，居中，可调整大小，没有最大化以外的特殊行为。
- 启动参数 `--settings`（项目负责人确认）：已经运行时再启动 `lextrail-desktop.exe --settings`，单实例回调打开设置窗口、不打开主窗口；不带参数仍打开主窗口。**程序还没运行时用 `--settings` 启动，也在启动后直接打开设置窗口**（不打开主窗口），所以快捷方式总是有用。用于 bench 和 e2e 脚本打开设置窗口（不用模拟点击托盘）。
- **浏览器快捷键**：WebView2 默认处理 F5 / Ctrl+R（刷新）、Ctrl+P（打印）、Ctrl+F（查找）等。录制时按这些键，页面不能刷新、不能弹出打印或查找；如果 WebView2 在页面之前就处理了（`preventDefault` 拦不住），就给设置窗口关掉浏览器快捷键（WebView2 的 `AreBrowserAcceleratorKeysEnabled`）。同时确认悬浮窗获得焦点时按 F5 不会重新加载页面（D010），会的话悬浮窗也关掉。

### 1.2 前端

- 第三个 Vite 入口 `apps/desktop/src/settings/`（`index.html`、`main.ts`、`App.vue`、各分类的组件、`ipc.ts`）。不引入 UI 组件库、路由、状态管理库（D010 的精神）；开关、按钮用原生元素加少量 CSS，样式和悬浮窗一致（目前没有深色模式，悬浮窗也没有）。
- 布局按以后会有多个分类设计：**左边分类列表，右边内容**。本次两类：
  - **快捷键**：划词翻译的快捷键；连按两次 Ctrl+C 开关。
  - **隐私**：不记录查询历史开关。
  - 以后的分类（悬浮窗、AI、同步、数据包、通用，见 `ARCHITECTURE.md` 第 12 节）直接加在列表里。选中的分类只在页面内存里，不需要路由。
- **录制框用按钮等不可编辑的元素，不用 `<input>`**：可编辑元素获得焦点时中文输入法会处理按键（组字、截走字母键），录不到真实的组合。
- 前端只负责收集按键、显示 Rust 返回的结果；快捷键的解析、显示文字、限制和提示全部在 Rust（第三节），前端不重复实现。

### 1.3 权限（Tauri 2 ACL）

目前应用自己的命令不需要权限，任何窗口都能调用。本次改为**每个窗口只能调用自己的命令**：

- `build.rs` 用 `tauri_build::Attributes::app_manifest(AppManifest::new().commands(&[...]))` 列出全部应用命令，Tauri 为每个命令生成 `allow-<命令名>` 权限，未授权的窗口调用会被拒绝。
- `capabilities/popup.json`：`core:event:allow-listen` + 悬浮窗的四个命令（`hide_popup`、`popup_ready`、`popup_measured`、`popup_resize`）。
- `capabilities/settings.json`：只给设置窗口自己的命令（第五节），不给事件监听以外的核心权限（需要时再加）。
- 主窗口仍然不授予任何权限。
- 自动检查：单元测试读两个 capability 文件，核对每个窗口的命令列表和 `generate_handler!` 中的命令一一对应、没有交叉。

## 二、快捷键的格式

- 设置文件里仍是字符串，如 `lookup = "Ctrl+Alt+X"`。写回时统一成规范写法：修饰键按 `Ctrl`、`Alt`、`Shift`、`Win` 的顺序，主键用大写字母、数字或键名（`F8`、`Space`、`Insert`、`Up` 等），用 `+` 连接。手改的写法（`ctrl+alt+KeyX`）照样能读，下次从界面保存时改成规范写法。
- 必须有且只有一个主键；只有修饰键的组合（如 Ctrl+Alt）无效，Windows 的 `RegisterHotKey` 不支持。
- 解析、规范化和显示文字放在 `lextrail-config::hotkey`（与平台无关，单元测试覆盖），桌面端再转成 global-shortcut 插件的 `Shortcut`。录制时前端把 `KeyboardEvent.code` 和四个修饰键状态原样交给 Rust，由 Rust 换成主键，所以 `code` 到主键的对应关系也在这里测试。
- AltGr 在 Windows 上报告为 Ctrl+Alt，录出来就是 Ctrl+Alt+…；右侧修饰键与左侧相同（`RegisterHotKey` 不区分左右）。

## 三、快捷键的限制与提示

### 3.1 禁止（会让 LexTrail 自己失灵）

| 组合 | 原因（界面上显示） |
|---|---|
| Ctrl+C | 剪贴板兜底要模拟它复制选中文字（D043），连按两次 Ctrl+C 也会失效 |
| Ctrl+Insert | 终端里的剪贴板兜底要模拟它复制（D043） |
| Esc | 悬浮窗靠它关闭 |

- 只禁止这三个**完全相同**的组合（`RegisterHotKey` 按修饰键精确匹配，Ctrl+Shift+C 不影响模拟的 Ctrl+C）。
- 录到禁止的组合时直接显示原因、不能保存。录制中按 Esc 是"取消录制"，所以 Esc 本来也录不进去。

### 3.2 允许，但保存前提示会影响什么

系统查不出软件内部的快捷键，所以下面这些都允许，保存前在设置窗口内显示提示，用户点"仍要使用"后照常注册（点"重新录制"则不保存）：

| 情况 | 提示（示例） |
|---|---|
| Ctrl+V / X / Z / Y / A / S / F / P / N / W / T 等常用快捷键 | "所有软件里的粘贴都会失效"（按组合给出具体功能名） |
| 不带修饰键的单个字母、数字、空格、回车、退格、Tab、方向键等 | "所有软件里都无法再输入 X" |
| 只有 Shift 加字母或数字 | "所有软件里都无法再输入大写 X / 符号 !" |
| 常用软件冲突清单（第七节）里的组合 | "在 Visual Studio 中是'工具箱'，在那里会失效"（列出清单里的软件和功能） |
| 只有 Alt 加字母（没有 Ctrl / Shift） | "这类组合查词时会让 Windows Terminal 的选区消失"（D014 补充：屏蔽键只能退回 `0xE8`） |

- 规则和提示文字是一张表（`lextrail-config::hotkey` 里的数据，单元测试逐条覆盖），以后补充清单只改表。
- 一个组合可能有几条提示，全部列出。
- 不带修饰键的功能键（F1–F24）、Pause 等不提示；但清单里有冲突的照样提示（例如 F1 是很多软件的帮助、Snipaste 的截图）。
- 带 Win 键的组合：**本次不支持**，录到时提示"暂不支持带 Win 键的组合"（项目负责人确认）。理由：Win+字母大多被系统保留，注册会失败；录制时很多组合被资源管理器先拿走；按住 Win 时弹出悬浮窗的行为没有测过。

## 四、录制快捷键

1. 点"更改"进入录制状态：显示"请按下新的快捷键（Esc 取消）"。**进入录制前先停用当前的全局快捷键**（注销），否则按到当前组合会触发查词、窗口也收不到按键。
2. 录制中拦截全部按键（`preventDefault`），不让 Alt 激活窗口菜单、不让 Tab 移动焦点。按住修饰键时实时显示"Ctrl + Alt + …"。
3. 按下主键即录完：交给 Rust 检查（第三节），显示规范写法和检查结果；然后按第五节保存。
4. **按下没有反应**：被别的程序用 `RegisterHotKey` 注册的组合按下时，窗口只收到修饰键、收不到主键。所以按过修饰键、又全部松开、却没有收到主键时，显示"按下没有反应，可能被别的程序占用"，继续录制。（只按了修饰键再松开也会看到这句话，可以接受。）
5. **录完或取消后恢复**：录完时按第五节的结果注册（新的或恢复旧的）；按 Esc、点"取消"、录制中窗口失去焦点（切到别的程序）或关闭设置窗口，都恢复旧的快捷键。设置窗口被销毁时 Rust 端检查一次：仍处在录制状态就恢复旧的，保证不会因为页面出问题一直没有快捷键。
6. 录制状态只在 Rust 端记一处（`hotkey.rs` 的状态机），前端只发"开始 / 结束"。

## 五、保存与即时生效

### 5.1 换快捷键

状态机在 `hotkey.rs`，通过一个可替换的"注册器"接口调用 global-shortcut 插件，单元测试用假的注册器覆盖每条路径：

1. 新组合与当前组合相同：什么都不做（录制时停用的旧组合照常恢复）。
2. 被禁止：不保存，恢复旧的。
3. 有提示：等用户确认；用户放弃就恢复旧的。
4. **先注册新的**。失败：恢复旧的，显示原因（"可能已被其他程序占用"或"系统不允许注册这个组合"），设置文件不变。
5. 注册成功后**再写回设置文件**。写回失败：注销新的、恢复旧的，显示"无法保存设置文件：…"。保证设置文件和实际生效的快捷键一致。
6. 成功：注销旧的（录制时已注销，这里只更新状态），托盘提示恢复为"LexTrail"（如果启动时注册失败改过它），界面显示"已生效"。
7. **恢复旧的也失败**（录制期间被别的程序抢走，项目负责人补充）：界面显示"未生效"和原因，托盘提示同步改为"LexTrail（快捷键注册失败）"；设置文件不变，用户换一个能注册的组合即可。状态机测试覆盖这条路径（取消录制、新的注册失败、写回失败三种情况下恢复都失败）。

**任何时候都有一个可用的快捷键**：除了录制期间（用户主动停用），旧的快捷键只在新的已经生效后才放弃。唯一的例外是启动时就注册失败（没有旧的可恢复），这时界面显示"未生效：可能已被其他程序占用"，用户换一个能注册的组合即可。

"恢复默认"按钮等同于录到默认组合（D014 的默认值），走同一套流程。

### 5.2 两个开关

- **连按两次 Ctrl+C**（`[hotkeys] double_ctrl_c`）：打开时立即启动剪贴板监听，关闭时立即停止（`DoubleCopyListener` 被丢弃时注销监听、结束线程）。`PopupState.double_copy` 由 `OnceLock` 改为 `Mutex<Option<…>>`。监听启动失败时开关退回关闭，显示原因。管理员窗口提示里的"（需先在设置中打开）"随开关实时变化。开关旁写设置说明（D012 补充：无痕 / InPrivate 窗口和密码管理器复制的内容不会触发；只查词典里的单词和短语、句子；终端里不会触发）。
- **不记录查询历史**（`[history] record`，界面上是"不记录"，所以取反）：`HistoryService.enabled` 改为 `AtomicBool`，下一次查词起生效；已经记录的历史不删除（说明里写明，删除界面不在 M1）。
- 写回失败时开关退回原状态，显示原因。
- 这改变了 D012 补充里"和其他设置一样，启动时读一次，改设置后重启生效"：从设置窗口改的设置**立即生效**；手改设置文件仍然要重启（文件开头的注释照旧）。

### 5.3 设置文件

- 设置窗口保存时整个文件重写（`SettingsFile::save`，先写临时文件再替换；项目负责人接受，暂不用 `toml_edit`）。**手写的注释不会保留**，文件开头的说明改为："LexTrail 在你从设置窗口改设置时会重写本文件，手写的注释不会保留；手改后请重启 LexTrail。"
- Rust 端在应用状态里保存一份当前设置（`SettingsService`：内存中的 `Settings` + `SettingsFile`），每次修改在它上面改一项、整份写回，不会覆盖掉别的项。
- **保存前检查文件有没有被手动改过**（项目负责人补充）：记下上次读或写之后文件的修改时间；保存前再看一次，不同（或文件被删掉）就不覆盖，提示"设置文件被手动修改过，请重启 LexTrail 后再修改"，这次修改不生效（开关退回、快捷键恢复旧的）。`lextrail-config` 提供带修改时间的读写，单元测试覆盖"没改过""改过""被删掉"。
- 启动时读到的设置文件来自更新版本（`NewerVersion`）时：设置窗口只读，显示"设置文件来自更新版本的 LexTrail，不能在这里修改"。

## 六、Rust 端命令（只授予设置窗口）

| 命令 | 作用 |
|---|---|
| `settings_get` | 当前设置和快捷键状态（规范写法、显示文字、是否已生效及原因、是否只读） |
| `hotkey_recording(active)` | 开始录制（停用当前快捷键）/ 取消录制（恢复） |
| `hotkey_check(keys)` | 检查一次按键（`code` + 修饰键）：规范写法、显示文字、禁止原因或提示列表 |
| `hotkey_apply(accelerator, confirmed)` | 按 5.1 换快捷键；有提示而 `confirmed` 为 false 时只返回提示 |
| `settings_set_double_ctrl_c(on)` | 5.2 |
| `settings_set_record_history(on)` | 5.2 |

命令都很快（注册快捷键、写一个小文件），在 Tauri 命令线程上同步完成。

## 八、测试

### 8.1 单元测试

- `lextrail-config::hotkey`：解析（大小写、`KeyX` / `X`、空白、重复修饰键、只有修饰键、两个主键）、规范写法、显示文字、`code` 到主键、禁止表、提示表逐条。
- `hotkey.rs`：换快捷键状态机（假注册器）：相同组合、禁止、提示未确认、新的注册失败、写回失败、成功、录制中窗口销毁、启动时就失败后再换。
- 开关：连按监听启停（假的启动函数）、历史开关取反。
- `tray.rs`：菜单顺序和 id。
- 权限：capability 文件与命令列表对应（1.3）。
- 前端：录制组件只收集按键，逻辑在 Rust；Vitest 仍是单独的 M1 任务，本次不引入。

### 8.2 自动检查（模拟按键，项目负责人同意后运行，全部用临时设置目录）

- `tools/e2e/settings-e2e.ps1`（新）：`--settings` 打开设置窗口 → 用 UI Automation 点"更改" → 模拟按下新组合 → 核对界面显示、设置文件已写回 → 在测试页里用新组合查词（`popup-e2e.ps1` 的做法核对悬浮窗内容）、旧组合不再触发。
  - 占用：脚本自己用 `RegisterHotKey` 先占住一个组合，录这个组合时应看到"按下没有反应，可能被别的程序占用"；用"恢复默认"之类的路径让注册失败时，应保留旧的并显示原因（旧组合仍能查词）。
  - 录制中关闭设置窗口：旧组合仍能查词。
  - 两个开关：打开连按后不重启就能连按查词；关闭后不再触发；不记录历史后查词，临时数据库里没有新记录。
- **按修饰键分类复测**（D014、R2-1、R2-2）：分别把查词快捷键设成下面五类，每类都测 Windows Terminal 选词（取到单词、选区保留，手动测试清单 5.1）和 VS Code 查词后按 Esc 再按 ↓（不框住"文件(F)"、不弹出菜单）：
  1. Ctrl+Alt（默认 Ctrl+Alt+X）
  2. Shift+Alt（如 Shift+Alt+X）
  3. 只有 Alt（如 Alt+X；预期 Windows Terminal 选区消失，和 3.2 的提示一致）
  4. Ctrl+Shift（如 Ctrl+Shift+F1，不需要屏蔽键）
  5. 不带修饰键的功能键（如 F8）
  每类再跑一次 `stuck-keys.ps1`（120 次，0 卡住）。真实键盘的同样测试放进手动测试清单 R9。
- 启动时注册失败：先用脚本占住默认组合再启动应用，核对提示框写着"右键托盘图标 → 设置…"。

### 8.3 性能

`lextrail-bench quick` 重测，结果追加到 `m0-benchmark.md` 的"历次重测"；新增一项"**设置窗口打开又关闭后**"的挂起内存（bench 用 `--settings` 打开设置窗口、等页面加载完、发 `WM_CLOSE` 关掉，再查一次词、等挂起后测）。设置窗口和悬浮窗同源（同一个 WebView2 环境），可能共用渲染进程，关掉设置窗口后进程不一定退出。**挂起内存以实测为准**，不预先假定回到约 83 MiB；没有回到时先把数据交给项目负责人，再决定怎么处理。
