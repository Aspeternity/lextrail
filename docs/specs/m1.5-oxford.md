### 0.7 补充数据（2026-10-22）

**a. 源 HTML 自带的编号**

| 元素 | 总数 | 带 `id` 属性 | 说明 |
|---|---|---|---|
| 义项 `t-sn-g` | 97,445 | 2,853（2.9%） | 主义项 2,708 / 77,738；习语内 23 / 11,819；短语动词内 121 / 4,190；派生词内 1 / 3,698 |
| 习语 `t-idm-g` | 11,107 | 241 | 只有 175 个不同的值，有重复 |
| 短语动词 `t-pv-g` | 3,270 | 251 | 不重复 |
| 派生词 `t-dr-g` | 6,170 | 416 | 不重复 |
| 其他（`t-subentry-g`、`t-top-g`、`t-v-g` 等） | — | 3,149 | |

- 全部 6,844 个不同的 `id` 值中，57 个出现在两个以上元素上（共 123 个元素）。
- 这些 `id` 是交叉引用的跳转目标：带 `#` 锚点的 `entry://` 链接 566,328 处（按词条去重），其中指向元素 `id` 的 10,455 处，其余指向说明页（发音符号表等）的段落。
- 义项没有序号属性：45,673 个义项带 `n` 属性，但值全部为空；页面上的序号由显示顺序决定。
- 同一批导出的繁体版（10 版）对照：49,751 个 `data-hkoup-entry` 完全相同，每个编号的词头和义项个数都相同；但有 5,375 个词条（10.8%）的元素 `id` 集合不同。
- 结论：源 `id` 覆盖太少、有重复、在繁简两版之间都不一致，**不能用作义项编号**；用"词条编号 + 序号"。`data-hkoup-entry` 在繁简两版之间一致，但只有一批导出，无法验证不同批次之间是否稳定。

**b. 同一词条的多份记录**

- 带词条编号的记录 149,396 条（另有 1,625 条说明页，合计 151,021），对应 49,751 个词条。
- **所有词条的多份记录逐字节相同**（每个词条只有 1 种 HTML）；记录之间只有查询键不同。转换时每个词条只需解析一次。

**c. 一个查询键对应多个词条**

- 词条的查询键（区分大小写，不含说明页）123,365 个，其中对应两个以上词条的 21,032 个。
- 这些键在 MDX 中的记录顺序：
  - 按词条编号升序：16,025 个（76.2%）；
  - "和键完全相同的词头在前，其余在后，两组内各按词条编号升序"：共 19,469 个（92.6%，包括上一行）；
  - 其余 1,563 个（7.4%）找不到规律（试过同形词编号、词性、词头字母顺序、词头长度），多数是两个词条都把这个键当作变形或变体。
- 词条编号本身大致按词头字母顺序（49,750 对相邻编号中 4,554 对词头"倒序"，主要是大小写和标点的排序差别）。词头相同的 4,064 组中：33 组都有同形词编号，按编号升序；其余 4,031 组是不同词性，先后没有固定的词性顺序（名词在动词前 1,623 组，动词在名词前 825 组，形容词在名词前 488 组……）。
- 结论：MDX 的顺序不可靠，查询结果的顺序由我们自己定（spec 中规定）。
- **一个键既是某词条的词头、又通向另一个词条**（例如过去式本身也是一个词）：6,181 个。在另一个词条里的关系：变体 2,923，变形（`t-vp`、`t-if`）1,719，派生词 104，习语 1，无法直接按文字对上（大小写、空格、连字符等差别）2,663。其中 5,944 个在 MDX 中是"本身是词头的词条"排在前面，237 个交错。
  这 2,663 个按大小写、空格、连字符、重音规范化，并用规则变形、ECDICT 的 `forms` 表再分一次后，只剩约 165 对分不了类（见 e）。

**d. 义项编号用的数据**（2026-10-22 第二次补充）

"词头 + 同形词编号 + 词性"（词头去掉音节点，区分大小写；词性取词头块里的全部词性）：

- 49,751 个词条中有 49,732 个不同的值；**不唯一的 19 组，每组 2 个词条，共 38 个**。19 组的两个词条编号都相邻；18 组有词性，1 组没有词性（全书没有词性的词条共 1,484 个）。
- 这 19 组还能怎么区分：17 组第一个英文释义不同；1 组义项个数不同（1 个对 3 个）；1 组英文部分完全相同（只差一段文字和一个链接，是源数据里几乎重复的两个词条），只能靠先后顺序。19 组中 18 组每个词条只有 1～2 个义项。加上音标、带音节点的词头也区分不开（仍是 19 组）。

义项指纹（英文释义去掉首尾空白、连续空白合并为一个后的哈希）：

- 97,445 个义项中 90,904 个有英文释义；**没有英文释义的 6,541 个**：只有交叉引用 2,906，只有例句 2,423，只有语法标注（多数是一个带链接的语法标注）1,114，只有搭配句型 66，其他 32。
- 没有英文释义时用"义项的英文文字"代替：义项内的全部文字，去掉中文（`t-chn` 和中文、全角字符）和嵌在义项里的习语，保留例句英文、交叉引用、语法标注。
- 用"英文释义，没有时用上面的代替文字"做指纹：**同一组内（主义项、某一条习语、某一条短语动词、某一个派生词）重复的只有 1 处**；同一词条内跨组重复 108 处（90 个词条，多是习语和主义项释义相同）。

# spec 正文（2026-10-22 批准）

> 数字都来自第 0 节。选择和批准时的修改见第 14 节。

## 1. 范围

M1.5 做：
- 转换工具：牛津 MDX（和 MDD 中的音频文件名）→ 我们自己的 SQLite 文件（"扩展词典"）。
- `lextrail-dict` 读扩展词典，与 ECDICT 合并成一个查询结果。
- 设置窗口："扩展词典文件夹"、牛津词典状态和开关。
- 悬浮窗显示牛津词条（修改 D046）。
- ECDICT 音标改成和牛津一致的写法。
- 发音：按第 9 节的选项决定。

不做：对外分发（M5 数据包）、繁体版、8 版 / 9 版、牛津其他词典（短语动词、习语词典视情况，见 ROADMAP）、插图、用法说明框的显示（只存文字）、话题标签的显示、生词本相关的任何功能（M3）。

## 2. 文件与位置

### 2.1 源文件

转换工具用命令行参数指定 `.mdx`（`--mdx`）和 `.mdd`（`--mdd`，只读文件名列表用；可以给多个），不写死任何路径。项目负责人的源文件在 `D:\LexTrailData\oxford-source\…`，只出现在 STATUS 和命令示例里，不出现在代码中。

### 2.2 扩展词典文件夹

- **默认**：`%LOCALAPPDATA%\io.github.aspeternity.lextrail\dicts\`（Tauri 的 `app_local_data_dir()` 下的 `dicts` 子文件夹；和 `lextrail.db` 同一个父文件夹，D040 不变）。
- **文件名**：`oalecd10.db`（扩展词典）。第 9 节如果选提取音频，再加 `oalecd10-audio.db`。程序只认这两个固定文件名，不扫描文件夹里的其他文件。
- **设置**：`settings.toml` 新增

  ```toml
  [dictionaries]
  # 扩展词典文件夹；空 = 默认位置
  folder = ""
  # 使用牛津词典（文件存在时）
  oxford = true
  # 悬浮窗显示牛津的英文释义（关掉后随例句折叠，7.2）
  english_definitions = true
  ```

  缺少这一节时用默认值（D035）。设置窗口里"选择文件夹…"和"恢复默认"两个按钮，不手输路径。
- **设置文件会漫游**（D035），另一台电脑上这个文件夹可能不存在：**文件夹或文件不存在一律当作"没有牛津数据"**，查词和 M1 完全一样，不弹框、不写错误日志（只在 debug 日志里记一行）。设置窗口显示状态（2.3）。
- 项目负责人自己的转换结果放 `D:\LexTrailData\dicts\`，在设置窗口里选这个文件夹即可。

### 2.3 状态（设置窗口显示，查词时不提示）

| 状态 | 设置窗口显示 |
|---|---|
| 文件夹不存在 | 找不到文件夹（路径） |
| 文件夹里没有 `oalecd10.db` | 没有找到牛津词典 |
| 文件打不开 / 不是扩展词典 / 格式版本不认识 | 牛津词典文件无法使用（原因一句话），查词不用它 |
| 正常 | 牛津高阶英汉双解第 10 版 · N 个词条（转换于某日） |
| 正常但开关关闭 | 同上，加"未启用" |

- **何时生效**：改文件夹、开关后立即生效：关闭已打开的扩展词典连接，下次查词时按新设置打开。查词时打开失败也按"没有牛津数据"处理，并让设置窗口下次显示原因。
- 打开时检查 `meta`（第 4 节）：`format = "lextrail-ext-dict"`、`format_version` 认识、`source = "oalecd10"`；否则拒绝。

## 3. 转换工具

- 位置 `tools/oxford-builder`，crate 名 `lextrail-oxford-builder`（D001）。和 `dict-builder` 共用 `lextrail-dict` 里的规则（规范化、后缀规则、音标写法、义项编号、指纹），规则只写一处（D038）。
- 读取：`mdictlib = "=0.2.8"`，`default-features = false`（不开 `lzo`），只在这个工具里依赖（D050）。
- HTML 解析：`scraper`（**ISC** 协议，基于 html5ever）。它依赖的 `selectors`、`cssparser` 是 **MPL-2.0**（文件级弱 copyleft：只要求修改这些库自身的文件时公开修改，不影响我们代码的协议）。桌面程序通过 Tauri（`tauri-utils`、`wry` → `dom_query` → `selectors`）本来就依赖 MPL-2.0 的库，而且 `scraper` 只在转换工具里用，所以可以用。选择理由：成熟、CSS 选择器写法和第 0 节的结构描述一一对应；性能够用（只解析 49,751 个词条）。
- 用法：

  ```
  cargo run -p lextrail-oxford-builder --release -- --mdx <源 .mdx> --mdd <源 .mdd> --mdd <源 .1.mdd> --ecdict data/build/lextrail-dict-core.db --out <输出文件夹> [--previous <旧 oalecd10.db>] [--report <报告.json>]
  ```

  `--out` 是文件夹，输出 `oalecd10.db` 和 `oalecd10-audio.db`（第 9 节）两个文件。`--ecdict` **必需**：关系判定（6.1）要用 ECDICT 的 `forms` 表定变形种类。

- 步骤：
  1. 读全部记录，按 `data-hkoup-entry` 分组；没有编号的 1,625 条说明页跳过。同一词条的多份记录应当逐字节相同（0.7 b）；**不同时报告并停止**（说明源文件和调研时不一样，规则要重新看）。
  2. 每个词条只解析一次，按第 0.3 节取字段。每个元素按类名分为"取字段 / 已知忽略 / 未知"；未知类名、该有却没取到的字段计数输出到报告（只有类名和个数，不含内容）。
  3. 生成稳定编号和指纹（第 5 节）。
  4. 判定每个查询键和词条的关系，算好顺序（第 6.1 节），存进数据库。
  5. 有 `--previous` 时生成新旧编号对照（第 5.4 节）。
  6. 提取词头和变形的发音（第 9 节方案 C）到音频文件。
  7. 写 `meta`，输出报告。
- **写文件的方式**（不留下写了一半的文件）：
  - 先在**输出文件夹里**建临时文件（`oalecd10.db.tmp-<随机>`）写入；最后用 `VACUUM INTO` 把整理好的数据库直接写到输出文件夹里的第二个临时文件，再改名替换目标文件。SQLite 自己的临时文件（建索引排序等）也放到输出文件夹（转换工具启动时把进程的 `TMP`/`TEMP` 设为输出文件夹），不写 `%TEMP%`（C 盘）。
  - 开始前检查目标文件能否替换：被占用（程序正在使用）时**停下**，提示"LexTrail 正在使用这个文件，请先退出 LexTrail 或在设置里关掉牛津词典"，不写任何文件。
  - 任何一步失败（包括 Ctrl+C）都删除临时文件；目标文件保持原样。两个输出文件都先写成临时文件，**全部写完后**一起检查目标是否被占用，再依次改名替换（先音频后文字）：文字这一步失败时两个旧文件都不变（测试覆盖）。
- **可重复**：同一份源文件、同一版本的工具、**同一版 ECDICT 词典**，输出的数据库内容完全相同（除了 `meta.built_at`）；测试覆盖。
- 报告（终端 + 可选 JSON，只有统计）：词条、义项、例句、习语、短语动词个数；各字段覆盖；未知类名；分不了类的键个数（预期约 2,352，0.7 e）；没有指纹或组内指纹重复的义项个数；耗时。
- 预计：读 MDX 约 4 s，解析 20–60 s；输出 35–45 MiB（0.6）。

| 表 | 内容 |

## 5. 稳定的义项编号（方案 B，D052）

### 5.1 编号规则

1. **带来源**：编号以 `oalecd10` 开头。
2. **组**：主义项 `s`；第 n 条习语 `i<n>`、第 n 条短语动词 `p<n>`、第 n 个派生词 `d<n>`。n 是这个元素（`t-idm-g` / `t-pv-g` / `t-dr-g`）在词条 HTML 中按出现顺序的序号，从 1 开始；嵌在主义项里的习语（0.7 d，228 个）也按出现顺序算进习语。
3. **序号按源文件结构数**：义项序号 = 它在所属组中是第几个 `t-sn-g`（从 1 开始，与书上印的序号一致）。**不管我们导入或显示了什么**：转换规则以后跳过、合并或新增字段，都不改变序号；没有 `t-sn-g` 的组（2,475 个，0.7 d）只有组编号，没有义项编号。
4. 组本身也有编号（如习语 `oalecd10/…/i3`），M3 收藏习语时用。
5. **指纹**：每个义项存英文释义的哈希（NFC、去掉首尾空白、连续空白合并为一个空格后的 SHA-256，取前 16 个十六进制字符）；没有英文释义的 6,541 个义项用"义项英文文字"代替（0.7 d 的定义），值前加 `alt:` 区分。组指纹 = 组标签文字的哈希。
6. 编号的计算函数放在 `lextrail-dict`（转换工具和测试共用），单元测试用自己写的假 HTML 覆盖规则 2、3。

### 5.2 方案 A：`data-hkoup-entry` + 序号（未选，留作记录）

例：`oalecd10/12345/s/2`。

### 5.3 方案 B（已选）：自己的"词头 + 同形词编号 + 词性" + 序号

- `entry_key` = 词头（去掉音节点，区分大小写）`|` 同形词编号（没有为空）`|` 词性（词头块中的全部词性，逗号分隔；没有为空），19 组重复的（0.7 d）在后面加 `|2`（按源文件先后，先出现的不加）。
- 编号中的 `/`、`|`、`%` 按百分号编码。例（自编词条）：`oalecd10/blorft||noun/s/2`、`oalecd10/blorft|2|verb/i1/1`。
- 数据库里分列存（来源、`entry_key`、组、序号），字符串形式只用于对外（M2 提示词里另用短编号，M3 存这个字符串）。

### 5.4 换批次时对照新旧编号

转换新批次时给 `--previous 旧库`：
1. 新库中有同一个编号、且指纹相同 → 不变。
2. 否则，在"同一个词条"（按 `entry_key`；找不到时按 `source_entry`）的同类组中找相同指纹 → 记入 `sense_renames(old_id, new_id, how)`。
3. 再找不到时在全书找唯一相同的指纹 → 同上，`how` 标明"跨词条"。
4. 仍找不到的，**在锚点之间按顺序配对**（记 `changed`，内容改过、引用仍然有效，M3 决定怎么提示）：
   - 范围：同一词条（同第 2 条）同一个组里的义项序列；组本身（同一词条的 i / p / d 各自的序列）也这样处理，先处理组，义项在旧组对照到的那个新组里配对（主义项组 `s` 对 `s`；旧组被删或跨词条时它的义项不配对）。
   - 锚点：不变的，或第 2 条对照到这个新组（序列）里的旧义项。锚点按旧序号排好后，新序号也必须递增；不递增（顺序被调过）时这个序列不配对。
   - 配对：相邻两个锚点之间（以及第一个之前、最后一个之后），取没对照上的旧义项和没被任何旧义项占用的新义项：个数相同时按顺序配对，`new_id` 是配到的新编号（不一定等于旧编号）；个数不同时都不配对。
5. 仍没有的 → `sense_renames(old_id, NULL, 'removed')`，报告个数。

例（字母是指纹，大写表示改过措辞）：`[a,b,c] → [a,B,c]`：s/2 → s/2 `changed`；`[a,b,c] → [b,c]`：s/1 `removed`（b 之前旧的 1 个、新的 0 个）；`[a,b,c] → [b,C]`：s/1 `removed`、s/3 → s/2 `changed`；`[a,b] → [n,a,B]`：s/2 → s/3 `changed`；`[a,b,c] → [B,c]`：s/1、s/2 都 `removed`（分不清删的是哪个）。单元测试覆盖这些、插入一个义项、顺序调过、组的配对。

对照表只覆盖"上一次转换 → 这一次"。用户跳过中间版本时（手里是第 1 版的引用、装的是第 3 版）的累积对照，到 M5 做数据包时再定。

程序打开新库时，M3 的收藏 / 复习卡按 `sense_renames` 改写引用（M3 实现，M1.5 只负责生成对照表）。

### 5.5 比较与推荐

| | 方案 A | 方案 B |
|---|---|---|
| 唯一 | 天然唯一 | 19 组需要加 `|2`（38 个词条） |
| 换批次时中间多 / 少一个词条 | 后面所有编号错位：几乎每个义项都要靠第 5.4 节的指纹找回，指纹相同的义项（1 处组内重复、跨词条的相同释义）可能找错 | 不受影响，只有改动过的词条要找 |

## 6. 查询与合并

### 6.1 键和词条的关系（转换时判定并存储，查询时不现算）

转换工具对每个"键—词条"判定一种关系（按下表顺序，取第一个成立的），存进 `keys.relation`：

| 关系 | 判定 | 显示（`relation` 文字） |
|---|---|---|
| `headword` | 键 = 词头，或只差大小写、空格、连字符、标点、重音 | — |
| `inflection` | 键是 `t-vp` 中的变形；`kinds` 取 `form` 属性（`thirdps` 第三人称单数、`past` 过去式、`pastpart` 过去分词、`prespart` 现在分词、`neg` 否定式、`short` 缩写式） | "find 的过去式、过去分词" |
| `inflection` | 键是 `t-if` 中的不规则变形；种类由 ECDICT `forms` 表或后缀规则判断，判断不了为空 | 种类为空时"X 的变化形式" |
| `inflection` | 键是词头（或变体、派生词）的规则变形（源 HTML 没写出，0.7 e 共 35,801 对）：后缀规则 + 原形词性定种类（`-s`：名词为复数、动词为第三人称单数，两种词性都有时两个都写）；ECDICT `forms` 表有时以它为准 | 同上 |
| `variant` | 键是 `t-v` 中的变体，或英美拼写差别 | "X 的另一种写法" |
| `derivative` | 键是 `t-dr` 派生词（或其规则变形） | "X 的派生词" |
| `idiom` / `phrasal` | 键是整条 `t-idm` / `t-pv`（去掉 sb、sth 等占位词） | "X 词条中的习语 / 短语动词" |
| `idiom_part` / `phrasal_part` | 键是习语 / 短语动词的一部分（`snib` 之于 "blorf the snib"） | 同上 |
| `other` | 都不是（预计约 2,352 对，1.57%） | 不写关系；只在没有任何其他结果时显示（6.3） |

`via` 存关系依据的那个形式（变体的写法、派生词的词头等），变形种类存 `kinds`。

实现时补充的判定细节（2026-10-22，第一次真实转换后）：

- **变形种类要和词性相符**：复数要求名词（或代词、数词、缩写、符号），第三人称单数和 `-ed` / `-ing` 要求动词，比较级、最高级要求形容词、副词、限定词或代词；没有词性的词条都接受。ECDICT `forms` 表给出的种类也按这条过滤（ECDICT 不分词性）：`found` 对动词 find 是 `inflection`，对名词 find 是 `other`；`blorfer` 不是动词 `blorf` 的比较级（而是派生词）。
- **有变形表的原形不再推断动词变形**（2026-10-22 第 3 步补充）：原形（词头、变体、派生词）自己有 `t-vp` 变形表（表的 `root` 就是这个原形）、而表里没有这个键（也不是英美拼写差别）时，ECDICT `forms` 和后缀规则推断出的动词变形种类（第三人称单数、过去式、过去分词、现在分词）不再用。ECDICT 不分同形词：`lay` 原来既是 lie¹（躺）也是 lie²（说谎，表里写 lied）的过去式，现在只对 lie¹。变体的变形不受影响（civilize 的表不列 civilise 的变形，`civilises` 仍是 civilise 的变形）。因此从 `inflection` 变成 `other` 的有 81 对、52 个键（例：`lain` 对 lie²、`waked` 对 wake、`blowed` 对 blow、`shrunken` 对 shrink、`shedded` 对 shed、`tangos` 对动词 tango；`ageing` 对动词 age（表里写 aging）、`wedding` 对 wed（表里没有 -ing 形式）——这两个有自己的词条）。最初按"所在组有变形表"判断时有 999 对，其中多数是 `-ise` 拼法变体的变形，所以改成只看原形自己的表。
- **多词、带连字符、带重音的键**：后缀规则和 ECDICT `forms` 也用在最后一个词和第一个词上（`bear markets`、`knock-downs`、`maids of honour`）；去掉重音再判断（`cortèges`）。
- **习语、短语动词中的占位词**（`sb`、`sth`、`oneself` …）和 `↔` 不计：`put off`、`putoff` 都是 `put sb↔off`。
- 比较文字时还忽略引号 `‘’“”"` 和 `™` `®`（`ext::text::fold_for_match`）；英美拼写差别加了 `disc` / `disk`。
- `via`：`inflection` 是原形（词头、变体或派生词），`variant` 是变体写法（英美拼写差别时是词头），`derivative` / `idiom` / `phrasal` / `idiom_part` / `phrasal_part` 是那个派生词、习语、短语动词；`headword`、`other` 为空。
- `keys.ord`：同一个键（不区分大小写）的各行按关系、词条词头的 ECDICT 词频、同形词编号、源文件先后排；大小写和句首规则在查询时再按 6.3 调整。`entries.ord`：同一词头（不区分大小写）的词条按同形词编号、源文件先后。

`keys.ord` 在转换时算好（6.3），查询时按它排序。同一个词头的多个词条（同形词、不同词性）按同形词编号、再按源文件先后（`source_entry` 升序）排——MDX 的记录顺序不可靠（0.7 c），不用它。

### 6.2 查询步骤

沿用 `m1-dict.md` 第 8 节，牛津数据在时：

1. 规范化（同第 8 节第 1 步）。
2. **查牛津键**（不区分大小写；带连字符时再试"连字符换成空格""去掉连字符"，0.5 中 `state-of-the-art`、`multi-task` 这类）。查到 → 按 6.3 组织结果，ECDICT 补标签（6.4）。
   - **牛津查到的词条里没有一个以这个键为词头、键也不是整条习语 / 短语动词**（6.3），**而 ECDICT 有这个键自己的词条**（不只是"xx 的过去式"之类说明，即 M1 的 `is_form_note` 为假）时，**ECDICT 的词条也给出**：按 M1 的方式显示（每个词性一行），带关系说明（"encode 的现在分词"）：**只用牛津的 `inflection` / `variant` / `derivative` 关系**；牛津只有 `idiom_part` / `phrasal_part` / `other` 关系时用 ECDICT `exchange` 的，都没有就不写（否则会出现"xx 词条中的习语"，而那个习语词条按 6.3 又不显示）。键是整条习语 / 短语动词时不补 ECDICT 的词条（`put off`、`give up`、`a can of worms`：显示牛津的组），只有那些组都没有释义、只有交叉引用时才补。注明来源 ECDICT。它和牛津词条的先后按 6.3 的"标记"规则（用 ECDICT 自己的标记）。数据见 0.7 g（全书 27,184 个键，论文 209 个词）。
   - **牛津对这个键只有 `other` 关系**（全部关系都是 `other`，1,540 个键，3.1）→ 按"牛津键查不到"处理，走第 3 步；第 3 步也没有结果时才显示 `Related`（6.3）。
3. 牛津键查不到 → 走 ECDICT 原来的流程（`exchange` 词形、后缀规则、短语）。**如果 ECDICT 还原出的原形牛津有**（0.5 中经词形还原查到的 4 个这类），原形用牛津词条，角色 `Lemma`，关系文字用 ECDICT 的。原形是牛津的整条习语 / 短语动词时也算（`gave up`、`putting off`、`puts off` → ECDICT 还原到 give up / put off → 显示牛津的 give / put 词条，那个短语动词组展开；先找词头，没有词头才找整条短语）。
4. 牛津和 ECDICT 都查不到 → 连字符拆分（8.1）不变；拆出的部分同样先查牛津。
- `is_word`（行末连字符判断）：牛津键也算词。没有牛津数据时与 M1 相同。
- `classify`（单词 / 短语 / 句子，D045）：牛津的多词键（习语、短语动词、复合词）算词典短语。
- `lemma()`（查询历史）：用牛津的原形。

### 6.3 多个词条的顺序

沿用 `m1-dict.md` 第 8 节的规则，只加牛津才有的关系：

- **大小写**：和选中文字大小写完全一致的在前；`sentence_start` 时小写的在前（牛津有大小写两个词条的情况，这条规则开始真正起作用）。
- **角色**：
  - `Query`：键是这个词条的词头（`headword`）。
  - `FormOf(关系)`：键是这个词条的词头，**同时**和另一个词条有 `inflection` / `variant` / `derivative` 关系——**显示时必须标出关系**（"found（find 的过去式、过去分词）""gaol（jail 的另一种写法）"）。
  - **有自己的牛津词条时去掉 `variant` 关系**（2026-10-22 第 3 步）：键有自己的牛津词条时，`variant` 关系的行不算：不标 `FormOf`，也不显示那个词条（`break` 不再是 recess 的另一种写法，`autumn`、`A`、`attack` 同理）。只针对牛津自己的词条；只有 ECDICT 补上的词条时照旧。**例外**：键自己的词条里有"没有释义、只有交叉引用"的义项或组，而且交叉引用指向那个变体词条（目标比较时去掉同形词编号、括号里的义项号和后面的词性：`programme noun`）时照旧显示（`gaol`：整个词条是"= jail, jailer"；`program`：一个义项是"(NAmE) = programme noun"）。`disk` 没有指向 disc 的交叉引用，只显示 disk。有自己的词条、又是别的词条的变体（没有 inflection / derivative）的键 5,709 个，落进例外的 2,665 个，其中 1,947 个自己的词条只有交叉引用，718 个还有正常释义（`area` 有一个义项是"= penalty area"，于是显示成"area（penalty area 的另一种写法）"，**待项目负责人确认**）。例：`gaol`、`program`、`abattoir`、`A-bomb`、`acclimate`、`advert`、`agism`、`airplane`、`alright`、`acid`。
  - **只写"xx 的过去式"之类说明的词条**（牛津的：每个义项都没有释义、只有 "past tense of" 这类交叉引用，232 个，如 `went`、`ate`、`bought`；ECDICT 的：M1 的 `is_form_note`）：在它指向的原形也显示时**不算键自己的词条**——排序（自己的词条在前）、隐藏含它的习语、6.2 第 2 步补 ECDICT 词条、`Related` 都按"没有自己的词条"处理。目标比较时去掉同形词编号（`lie1`）。232 个中 217 个的目标都在原形结果里；其余 15 个键里，5 个目标带同形词编号（`lain`、`rang`、`rung`、`tore`、`torn`，已按去掉编号比较），10 个牛津本身没给出原形关系（`abode`、`bade`、`begotten`、`cleft`、`clove`、`hove`、`shat`、`snuck`、`spake`、`sped`），这 10 个照常显示那个说明词条。
  - `Lemma`：通过 `inflection` / `variant` / `derivative` / `idiom` / `phrasal` 关系查到的那个词条（原形、主拼写、派生词、习语、短语动词所在的词条）。派生词、习语、短语动词查到时，这个词条显示时把对应的组展开放在最前（7.3）。
  - **整条习语 / 短语动词**（`idiom` / `phrasal`）：照常显示（角色、展开的组、上方说明"put off 是 put 词条中的短语动词"都按 7.3），不因为键有自己的词条而隐藏；它本身也算"键自己有词条"：含这个键的习语（`idiom_part` / `phrasal_part`）隐藏，不补 ECDICT 的词条（组都只有交叉引用时例外，6.2）。同时有自己的词头词条和整条短语（35 个键，headword 不计空格和连字符：`all in` 对 all-in 和习语 all in，`setup` 对 set-up 和短语动词 set up，`big deal` 对 big deal 和习语 big deal!）时两个都显示，和选中文字写法完全一致的在前（不区分大小写，空格和连字符算不同，不计重音符号和标点），都不一致或都一致时自己的词条在前。其中 20 个键的词头写法和键不同，多是连写键（`makeup`、`holdup`、`plugin`）。
  - ECDICT 补上的自己的词条（6.2 第 2 步）：和牛津的 `Query` / `FormOf` 同等对待，角色是 `FormOf`（有关系说明时）或 `Query`，来源标 ECDICT。
  - `Related`（新增）：`other` 关系查到的牛津词条，不写关系文字。**只在没有任何其他结果时显示**：牛津没有这个键的其他关系、ECDICT 没有它自己的词条、ECDICT 的词形还原也找不到原形。有其他结果时不显示。牛津只有 `other` 关系的键先按"牛津键查不到"走 6.2 第 3 步，第 3 步没有结果才到这里（统计见本节末）。

## 8. 音标写法统一

- 牛津：IPA，重音 `ˈ` `ˌ`、长音 `ː`、`ɡ`；happy 的尾音写 `i`（influence 一类的 `u` 同理）；英音中 `(r)` 表示连读 r。
- ECDICT（精简版 216,452 个音标；和牛津都有的单词 30,519 个用来核对）：旧式写法——重音 `'`，次重音 `,` 或 `.`，长音 `:`，`g`（另有 11,029 处写成 `^`，对照牛津，能对齐的 481 处都是 `ɡ`），短元音写 `i` `u`，短 o 写 `ɔ`、长 o 写 `ɔ:` 或 `ɒ:`，`ə:` 表示 `ɜː`；`e` 有三种写法：`ɛ`（U+025B，497 个音标）、`є`（U+0454，606 个）、`ε`（U+03B5，192 个）。

规则（放在 `lextrail-dict` 的 `normalize_phonetic`，`dict-builder` 生成时使用；按顺序）：

1. 去掉首尾空白；西里尔字母 `ә` → `ə`（M1 已有）。
2. 符号：`'` → `ˈ`；`,` `.` → `ˌ`；`:` → `ː`；`g` `^` → `ɡ`；`ɛ` `є` `ε` → `e`。
3. 长元音：`əː` → `ɜː`；`ɒː` → `ɔː`；`iː` `uː` `ɔː` 不变。
4. `i`、`u`（后面不是 `ː`）按位置：
   - 在元音后面（双元音 `ai` `ei` `ɔi` `au` `əu`）→ `ɪ` / `ʊ`（`ɔi` → `ɔɪ`，ECDICT 中 2,192 个音标有 `ɔi`）；
   - 在 `ə` 前面：所在音节重读（往前找，先遇到 `ˈ` / `ˌ` 而不是元音，或前面没有元音）→ `ɪə` / `ʊə`（here、tour 一类）；否则保留 `iə` / `uə`（media、actual 一类）；
   - 在词尾（字符串末尾或空格前），或紧接着别的元音 → 保留 `i` / `u`（happy 一类；ECDICT 中词尾 `i` 有 17,351 个音标）。判断"在词尾""在别的元音前"时**跳过中间的重音符号** `ˈ` `ˌ`（`ri'ækt` → `riˈækt`、`ə.bri:vi'eiʃən`、`.ækwi'es`，牛津都写 `i`；ECDICT 原始数据中约 3,045 个音标是这种情况，项目负责人 2026-10-22 补充）。"在 `ə` 前"只看紧接着的 `ə`；
   - 其他位置 → `ɪ` / `ʊ`。
5. `ɔ`（后面不是 `ː`）：后面是 `i` 或别的元音时保留 `ɔ`，否则 → `ɒ`。`ɒi` 也 → `ɔɪ`（实现时发现：ECDICT 有 469 个音标把 boy、oil、choice 一类写成 `ɒi`）。
6. ECDICT 的美式 `ou`（177 个，如 go）转成 `oʊ`，即牛津美音的写法，不改成英音的 `əʊ`（那是内容不同，不是写法不同）。

核对（各位置上牛津的写法，30,519 对）：

| ECDICT 的位置 | 牛津写法（对齐后计数） | 规则 |
|---|---|---|
| `i` 在词尾 | `i` 3,000，`ɪ` 450 | `i` |
| `i` 在 `ə` 前 | `i` 834，`ɪ` 694 | 按重读分（上面第 4 条） |
| `i` 在别的元音前 | `i` 132，`ɪ` 12 | `i` |
| `i` 在元音后（双元音） | `ɪ` 5,423，`i` 51 | `ɪ` |
| `i` 其他位置 | `ɪ` 12,438，`ə` 1,154，`i` 683 | `ɪ`（`ə` 是转写不同，不改） |
| `u` 在元音后（双元音） | `ʊ` 2,556，`u` 7 | `ʊ` |
| `u` 在 `ə` 前 | `ʊ` 240，`u` 135 | 按重读分 |
| `u` 在别的元音前 | `u` 38，`ʊ` 7 | `u` |
| `ɔ` + `i` | `ɔ` 56 | `ɔɪ` |
| `ɔ` 其他位置 | `ɒ` 709，`ɔ` 14 | `ɒ` |

（上表未计入第 5 条的 `ɒi` 和第 4 条的"跳过重音符号"。）

**转换工具完成后重算**（2026-10-22）。口径和上表不同，数字不能直接比：ECDICT 精简版中词头与某个牛津词条的词头完全相同、两边都有音标的 33,026 个词；和这个词头的任一牛津英音相同就算相同（牛津的 `(r)` 不计）。

## 10. 性能

- 扩展词典与 ECDICT 词典一样常驻：第一次查词时打开，`cache_size` 1 MiB、`mmap_size = 0`（D046）；只有托盘时不打开。预计常驻内存增加 1～3 MiB。
