# LexTrail 路线图

> 完成一项勾选一项（`- [x]`）。每个里程碑都有"完成标准"，全部满足后才能进入下一个里程碑。
>
> 规则：
> - 不要跳过里程碑，也不要提前实现后续里程碑的功能，除非项目负责人同意。
> - 开发中发现需要新增的任务，追加到对应里程碑末尾，并标注 `（新增）`。
> - 当前进度以 `STATUS.md` 为准。

## M0 · 项目骨架与性能原型

目标：搭好项目结构，并用实测数据验证"路线 A（Tauri/WebView 悬浮窗）"是否可行（D008、D009）。

- [x] 初始化 monorepo：Cargo workspace、pnpm workspace、目录结构（见 `ARCHITECTURE.md` 第 3 节）
- [x] 代码规范：`rustfmt`、`clippy`、TypeScript strict、ESLint、Prettier
- [x] GitHub Actions：每次推送自动运行格式检查、lint、测试、Windows 构建
- [x] Tauri 2 桌面应用骨架：托盘图标、托盘菜单、开机不显示窗口
- [x] 全局快捷键注册，注册失败时提示
- [x] 设置的读写（本地配置文件），API Key 存入系统凭据管理器
- [x] 悬浮窗：单独打包的轻量页面；在鼠标附近显示；Esc / 点击外部关闭
- [x] 悬浮窗生命周期：隐藏 → `TrySuspend` 挂起 → 快捷键 `Resume`；低内存通知时销毁；"内存优先"模式
- [x] 主窗口骨架：关闭时销毁
- [x] **性能测试**：按 `ARCHITECTURE.md` 第 10 节逐项实测，包括"挂起 2 小时后恢复"，输出报告到 `docs/specs/m0-benchmark.md`
- [x] 单实例：第二次启动时唤起主窗口（新增）

**完成标准**：性能报告完成，并在 `DECISIONS.md` 中记录"路线 A 确认"或"切换到路线 B"的结论。
